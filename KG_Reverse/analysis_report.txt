一、样本概况
======================================================================

1.1 KG.exe (主程序)
  - 大小: 47,185,920 bytes (~45 MB)
  - 架构: PE32 x86
  - 入口点: 0x00081E65 (push ebp 标准函数)
  - ImageBase: 0x00400000
  - 节区:
    .text     VA=0x00001000  ENT=6.645  [EW]   代码段
    .rdata    VA=0x000A2000  ENT=7.579  [W]     高熵数据段 (加密/压缩)
    .data     VA=0x02BA7000  ENT=3.950  [WR]    数据段
    .rsrc     VA=0x02C17000  ENT=5.669  [W]     资源段

  主要导入 DLL:
  - KERNEL32.dll: 进程操作、内存操作、反调试API
  - USER32.dll: 窗口管理
  - GDI32.dll: 图形设备
  - ADVAPI32.dll: 注册表
  - SHELL32.dll: Shell 操作
  - WINMM.dll: 音频 (waveOut, midi)
  - WS2_32.dll: 网络通信
  - VERSION.dll: 版本信息
  - ole32.dll, OLEAUT32.dll: COM 自动化

1.2 ExuiKrnln_Win32.lib (DLL)
  - 实际是 PE32 DLL
  - 大小: 2,355,712 bytes (~2.3 MB)
  - 架构: x86
  - 类型: CEF (Chromium Embedded Framework) 基于的 UI 框架
  - 厂商: www.exuik.com

三、绕过方案
======================================================================

3.1 反调试绕过 (KG_Bypass.c 已实现)
  原理: 通过 IAT Hook 替换函数指针

  Hook 目标:
  - IsDebuggerPresent -> 始终返回 FALSE
  - CheckRemoteDebuggerPresent -> 始终返回 FALSE
  - NtQueryInformationProcess -> 隐藏调试器 (class 7/30/31)
  - ZwQueryInformationProcess -> 隐藏调试器 (class 7/30/31)
  - OutputDebugStringA/W -> 静默

  编译 (Windows MinGW):
  i686-w64-mingw32-gcc -shared -o KG_Bypass.dll KG_Bypass.c -lws2_32

  注入方式:
  - AppInit_DLLs 注册表: HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Windows\LoadAppInit_DLLs = 1
    然后在 AppInit_DLLs 值中添加 KG_Bypass.dll 路径
  - Remote DLL 注入工具 (如 RemoteInjector, DLL Injector Pro)

3.2 卡密验证绕过
  方案 A - 静态 Patch:
  * 搜索验证字符串交叉引用
  * NOP 掉 call+test+jump 反调试模式 (FF15...85C0...74/75)
  * 修改验证后的条件跳转

  方案 B - MITM 代理:
  * 使用 mbSetProxy 设置本地代理
  * 拦截验证 API 请求
  * 修改服务器响应 (valid=false -> valid=true)

  方案 C - WebSocket 劫持:
  * Hook mbNetSetWebsocketCallback
  * 拦截验证消息
  * 修改消息内容为通过状态

3.3 ACE 反作弊绕过
  * 不加载 ACE-SSC64.sys 内核驱动
  * Patch SProtectSDK64.dll 加载检查
  * 禁用 ACE 相关服务 (sc stop AntiCheatExpert)
  * 修改进程黑名单检查

3.4 内核级操作
  * KG.exe 含完整内核驱动加载代码
  * ZwAllocateVirtualMemory 可操作任意进程
  * ZwProtectVirtualMemory 修改内存保护
  * 可用于读写游戏进程内存

六、关键发现总结
======================================================================

1. 二进制未使用传统壳 (UPX/Themida/VMProtect)，为原生 PE
2. .rdata 节区高熵 (7.579) 来自嵌入的压缩/加密数据
3. 使用 7 层反调试机制，包括内核级检测
4. 实现了完整的 ACE (AntiCheatExpert) 绕过
5. 通过 WebSocket + HTTP 实现卡密网络验证
6. UI 基于 Exui CEF 框架 (www.exuik.com)
7. 可通过 IAT Hook + WebSocket 劫持绕过验证
8. 支持内核级内存操作 (ZwAllocateVirtualMemory)
9. 目标游戏: League of Legends
10. 包含完整的驱动加载代码
