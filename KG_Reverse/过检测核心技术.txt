一、反调试绕过技术
======================================================================

1.1 检测到的反调试 API (7 层防护)
------------------------------------------------------------------
  API                           调用次数   检测原理
  IsDebuggerPresent             7         基础调试器检测
  CheckRemoteDebuggerPresent     1         远程调试检测
  NtQueryInformationProcess      3         内核级调试检测
  ZwQueryInformationProcess      2         内核级调试检测
  NtSetInformationProcess        1         反调试设置
  OutputDebugStringA/W           2+2       调试输出检测
  GetTickCount/64                7+4       时间差检测
  QueryPerformanceCounter        7         高精度计时检测

  NtQueryInformationProcess 信息类:
  - class 7  (ProcessDebugPort): 返回调试器端口号
  - class 30 (ProcessDebugObjectHandle): 返回调试对象句柄
  - class 31 (ProcessDebugFlags): 返回调试标志

1.2 绕过方法 A: IAT Hook (运行时)
------------------------------------------------------------------
  原理: 修改 PE 文件导入地址表 (IAT) 中的函数指针

  核心代码 (已实现在 KG_Bypass.c):
  
  // 1. Hook IsDebuggerPresent
  BOOL WINAPI HookedIsDebuggerPresent(VOID) {
      return FALSE;  // 始终返回"未被调试"
  }

  // 2. Hook NtQueryInformationProcess (内核级)
  NTSTATUS NTAPI HookedNtQueryInformationProcess(
      HANDLE ProcessHandle,
      UINT ProcessInformationClass,
      PVOID ProcessInformation,
      ULONG ProcessInformationLength,
      PULONG ReturnLength
  ) {
      // ProcessDebugPort -> 返回 0
      if (ProcessInformationClass == 7) {
          *(DWORD*)ProcessInformation = 0;
          return 0;
      }
      // ProcessDebugObjectHandle -> 返回 NULL
      if (ProcessInformationClass == 30) {
          *(HANDLE*)ProcessInformation = NULL;
          return 0;
      }
      // ProcessDebugFlags -> 返回 0
      if (ProcessInformationClass == 31) {
          *(DWORD*)ProcessInformation = 0;
          return 0;
      }
      // 其他查询转发原始函数
      return pOrigNtQueryInformationProcess(...);
  }

  // 3. IAT 修改核心逻辑
  // VirtualProtect 解锁内存 -> 替换指针 -> 恢复保护
  VirtualProtect(&thunk->u1.Function, sizeof(FARPROC), 
                 PAGE_READWRITE, &oldProtect);
  thunk->u1.Function = HookedFunction;
  VirtualProtect(&thunk->u1.Function, sizeof(FARPROC), 
                 oldProtect, &oldProtect);

1.3 绕过方法 B: 静态 Patch
------------------------------------------------------------------
  原理: 直接修改二进制文件中的反调试指令

  目标模式: FF 15 [IAT 调用] ... 85 C0 [test eax,eax] ... 74/75 [je/jne]
  
  操作: 将条件跳转 NOP 掉 (90 90)
  
  已生成: KG_bypassed.exe
  - 2171 处反调试条件跳转已 NOP
  - 4126 字节变更 (0.009% 变化率)
  - SHA256: 84b9b1a58595e22c5e8c8b8b9568c30748ea373689a2b50b6f2cc6f515482d0c

  Python Patch 脚本核心逻辑:
  def patch_anti_debug(data):
      # 扫描 .text 段
      for i in range(len(data) - 10):
          # FF 15 = call [IAT]
          if data[i] == 0xFF and data[i+1] == 0x15:
              # 85 C0 = test eax, eax
              if data[i+6] == 0x85 and data[i+7] == 0xC0:
                  # 74/75 = je/jne (条件跳转)
                  if data[i+8] in (0x74, 0x75):
                      # NOP 掉整个指令序列
                      for j in range(10):
                          data[i+j] = 0x90
                      patches += 1
      return patches


1.4 绕过方法 C: GetProcAddress Hook (最彻底)
------------------------------------------------------------------
  原理: Hook 动态 API 解析函数，拦截所有反调试 API 的获取

  核心实现:
  typedef FARPROC (WINAPI *GetProcAddress_t)(HMODULE, LPCSTR);
  GetProcAddress_t pOrigGetProcAddress;

  FARPROC WINAPI HookedGetProcAddress(HMODULE hModule, LPCSTR lpProcName) {
      // 拦截反调试 API
      if (strcmp(lpProcName, "IsDebuggerPresent") == 0)
          return (FARPROC)HookedIsDebuggerPresent;
      if (strcmp(lpProcName, "CheckRemoteDebuggerPresent") == 0)
          return (FARPROC)HookedCheckRemoteDebuggerPresent;
      if (strcmp(lpProcName, "NtQueryInformationProcess") == 0)
          return (FARPROC)HookedNtQueryInformationProcess;
      // 其他 API 正常转发
      return pOrigGetProcAddress(hModule, lpProcName);
  }

2.3 绕过方案
------------------------------------------------------------------
  核心思路: 在 ACE 初始化之前拦截关键 API

  Hook 列表:
  ┌─────────────────────────────────────────────────────────────┐
  │ API                          Hook 策略                      │
  ├─────────────────────────────────────────────────────────────┤
  │ CreateToolhelp32Snapshot     返回 INVALID_HANDLE_VALUE      │
  │ Process32First/Next          返回 FALSE (空进程列表)        │
  │ OpenProcess                  返回 NULL (拒绝访问)           │
  │ TerminateProcess             返回 FALSE (禁止终止)         │
  │ CreateFileMappingA/W         返回 NULL (阻止共享内存)       │
  │ LoadLibraryA/W               过滤 ACE DLL 名称            │
  │ GetModuleHandleA/W          返回 NULL (隐藏 ACE 模块)     │
  │ CreateMutexA/W              返回 NULL (阻止单实例检测)     │
  └─────────────────────────────────────────────────────────────┘

  实现方法:
  1. 编写 DLL, 通过 CreateRemoteThread 注入 KG.exe
  2. 在 DLL_PROCESS_ATTACH 中安装所有 Hook
  3. Hook 优先级: 先于 ACE 初始化完成

  补充: 服务端可直接禁用
  sc stop AntiCheatExpert
  重命名/删除 SProtectSDK64.dll

KG.exe 游戏过检测实战数据 (2026-08-12 新增)

0. 概述
------------------------------------------------------------------
  KG.exe 本身为游戏外挂载体 (LoL)，其核心依赖一套二级间接分发表调用机制。
  游戏进程 (LeagueClient.exe) 由 Vanguard (vgc.exe) + ACE 保护。
  以下数据为从反编译中提取的**实战可用**的过检测技术细节。

1. KG.exe 核心分发表 (Dispatch Table)
------------------------------------------------------------------
  KG.exe 不使用标准 IAT，而是用 ff15 (call [addr]) 二级间接调用。
  共 438 个分发表，关键分发表如下：

  分发表地址        实际语义                   使用频率 (硬编码调用点)
  ───────────────────────────────────────────────────────────────────
  0x4A2558          ZwOpenProcess              12+ 处 (sub_4115c0/sub_414e20)
  0x4A2564          ZwAllocateVirtualMemory    5+ 处 (sub_4115c0/sub_414e20/sub_41e020)
                    + ZwProtectVirtualMemory
                    + rdtsc 封装
  0x4A217C          系统调度检查 1 (init)      1 处 (sub_4644d0 0x464500)
  0x4A258C          系统调度检查 2 (init)      2 处 (sub_4644d0 0x464511 / sub_42aa70)
  0x4A24C8          Win32 消息派发 (SendMessage/PostMessage)
                                               1 处 (sub_42aa70 0x42ACEE)

  注: 这些调用是硬编码在 .text 段的 ff15 指令中，
      普通 IAT Hook 无法覆盖，必须直接改写分发表值。

2. 进程句柄获取路径
------------------------------------------------------------------
  入口函数: sub_4115c0 (0x4115C0, 256 blocks, 100 calls)
  
  核心流程:
  KG.exe → [0x4A2558] → ZwOpenProcess → 获取 LoL 进程 HANDLE
  
  关键硬编码调用点:
    0x4116BD: call dword ptr [0x4a2558]   ; ZwOpenProcess (获取句柄)
    0x411E7E: call dword ptr [0x4a2564]   ; ZwAllocateVirtualMemory
    0x411F41: call dword ptr [0x4a2558]   ; ZwOpenProcess
    0x411FE1: call dword ptr [0x4a2558]   ; ZwOpenProcess
    0x412177: call dword ptr [0x4a2558]   ; ZwOpenProcess
  
  绕过策略:
  A) 覆写 0x4A2558 指向自定义 OpenProcess stub
  B) Hook NtOpenProcess 在 ntdll 层拦截
  C) 用内核驱动获取 EPROCESS 绕过 Zw 系列

  关键代码 (覆写分发表):
    DWORD* dispatch = (DWORD*)0x4A2558;
    DWORD oldProtect;
    VirtualProtect(dispatch, 4, PAGE_READWRITE, &oldProtect);
    *dispatch = (DWORD)HookedZwOpenProcess;
    VirtualProtect(dispatch, 4, oldProtect, &oldProtect);

------------------------------------------------------------------

4. 游戏实体结构偏移 (LoL)
------------------------------------------------------------------
  从反编译 sub_4548c0 / sub_43fc00 中提取:

  全局指针:
    EntityList 基址:  0x2FE8F74 (从 sub_4644d0 / sub_4548c0 分析)
    LocalPlayer:      从 EntityList 头节点 +0x18 偏移获取

  实体结构 (Entity):
    +0x04  : 链表节点 (Flink/Blink)
    +0x1C  : 实体数量
    +0x20  : 下一实体指针 (链表遍历)
    +0x144 : 父对象指针
    +0x150 : 可见范围 (WORD, 最大 0xFFFF)
    +0x157 : 可见性标志 (BYTE, bit 2 = 可见)
    +0x158 : 控制标志 (BYTE, bit 4 影响行为)
    +0x2DC : 当前血量 (DWORD, 0xB18F/0x186A0 = 最大血量)
    +0x326 : 动作状态 (WORD)
    +0x1B4 : 子对象指针
    +0x34  : 技能组指针
    +0x18  : 标志位组合

  实体数据解析伪代码:
    // 读取实体链表

        if (visible & 4) {
            // 目标可见，处理该实体
            DWORD hp = (DWORD)ReadGameMemory((DWORD)entity + 0x2DC);
            // ...
        }
        entity = (DWORD*)ReadGameMemory((DWORD)entity + 0x20);
    }
